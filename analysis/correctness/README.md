# Conditional first-buzz correctness

One research line, three packages. Every model here answers the same question on
the same rows: **given the observed buzzer and the observed buzz position, was
the buzz correct?** None of them predict *who* buzzes or *when* — that is the
Stage-1 tossup model's job, and these studies condition on its outcome rather
than competing with it.

The shared protocol is fixed across all three packages: the 45,995 held-out
first buzzes of the five whole-game folds used by the saved simplex DD-Bernstein
3/3/2 reference (`holdout/game_splits.py`, seed 42). Feature fitting, candidate
selection, and thresholds use training games only. Because the same five folds
have been reused repeatedly, these are development comparisons, not an untouched
test result.

The consolidated finding is
[`docs/correctness-benchmarks.md`](../../docs/correctness-benchmarks.md) —
generated by `tossup_accuracy_study/report.py`, so edit that script rather than
the document. The publication-readiness assessment that opened this line is
[`paper-readiness-tossups/REPORT.md`](../../results/compirt/holdout/common/paper-readiness-tossups/REPORT.md).

## The three packages

| Package | Role | Results |
| --- | --- | --- |
| [`paper_readiness/`](paper_readiness/) | Fixed-specification baselines, the data/likelihood audits, and the shared feature and metric module every other package imports | [`holdout/common/paper-readiness-tossups/`](../../results/compirt/holdout/common/paper-readiness-tossups/) |
| [`tossup_accuracy_study/`](tossup_accuracy_study/) | Validation-selected point fits: question splines, frozen timing skills, boosted trees, the tree/spline ensemble, and the timing replay | [`holdout/common/tossup-accuracy-study/`](../../results/compirt/holdout/common/tossup-accuracy-study/) |
| [`bayesian_mark_study/`](bayesian_mark_study/) | Variational Bayes on the same design, plus the Bayesian/prefix mixture | [`holdout/common/bayesian-mark-study/`](../../results/compirt/holdout/common/bayesian-mark-study/) |

Package names match their result directory names deliberately, so a result
folder names the code that wrote it.

`paper_readiness/first_buzz_features.py` is the spine: it defines `ROOT` (the
saved reference run the folds come from), `load_first_buzzes`, and the shared
`metrics`. The other two packages and the archived `archive/frozen_skills/`
package all import from it, so changing it changes every comparison in this
directory.

## Running them

All commands run as modules from the repository root, in dependency order.

```bash
# 1. Baselines and audits — no fitting of the CompIRT models.
PYTHONPATH=. .venv/bin/python -m analysis.correctness.paper_readiness.audit_data
PYTHONPATH=. .venv/bin/python -m analysis.correctness.paper_readiness.run_correctness_baselines
PYTHONPATH=. .venv/bin/python -m analysis.correctness.paper_readiness.bootstrap_baselines

# 2. Point fits. run.py must precede the rest; the others read its saved folds.
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.run
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.boosting
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.summarize
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.export

# 3. Bayesian fits on the point study's exact inner splits.
.venv/bin/python -m analysis.correctness.bayesian_mark_study.run
.venv/bin/python -m analysis.correctness.bayesian_mark_study.blend
.venv/bin/python -m analysis.correctness.bayesian_mark_study.summarize
.venv/bin/python -m analysis.correctness.bayesian_mark_study.verify

# 4. Reports: the shared benchmark table, then the timing comparison.
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.report
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.evaluate_timing
.venv/bin/python -m analysis.correctness.tossup_accuracy_study.report_timing
```

`bayesian_mark_study/run.py` reads `tossup-accuracy-study/fold_*/inner_split.csv`
and asserts the split hashes match, so the two studies cannot silently drift onto
different folds.

## Replaying without refitting

Both `tossup_accuracy_study/predict.py` (the tree/spline ensemble) and
`tossup_accuracy_study/predictor.py` (the serialized correctness predictor) load
saved fold artifacts and score new rows with no fitting. The archived Pyro
reimplementation of the same two-stage idea,
[`archive/frozen_skills/`](../../archive/frozen_skills/README.md), imports this
package's features and its saved MAP fold artifacts.

## Tests

```bash
.venv/bin/python -B -m pytest -q analysis/correctness
```

Synthetic and closed-form checks only — no dataset, no fitting, nothing written
under `results/`. The repository check (`run_scripts/common/check_repo.py`) runs
this suite as "correctness study tests".

## Provenance note

These packages were regrouped under `analysis/correctness/` after their fits
completed, so saved artifacts under `results/` still record their original
`analysis/<package>/` paths. Run directories themselves were not renamed. Three
things bridge the gap:

- `tossup_accuracy_study/__init__.py` registers `analysis.tossup_accuracy_study`
  as an alias in `sys.modules` at import. The ten saved fold predictors
  (`fold_*/regularized.joblib`, `fold_*/frozen_skills.joblib`) were pickled under
  the old path and will not unpickle without it.
- `bayesian_mark_study/verify.py` translates the two dependency paths whose
  hashes were recorded before the move.
- `archive/frozen_skills/joint.py` installs the same alias locally around its own
  `joblib.load`.

Regenerating the saved predictors would make all three unnecessary.
